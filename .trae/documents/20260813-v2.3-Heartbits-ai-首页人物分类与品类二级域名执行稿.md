# Heartbits ai 首页人物分类与品类二级域名（执行稿）

## 0. 基本信息

- 文档类型：执行稿
- 版本：v2.3
- 日期：2026-08-13
- 需求来源：SEO 推广需要（按单一品类投放与收录）+ 产品品类扩展（人物从真人扩展到真人 + 动漫）
- 执行口径：以当前 Demo 表现为基线，描述本次迭代的目标形态；本期仅输出文档，不改代码
- 关联页面：首页（`/browse`）、新增的女人 / 男人 / 动漫三个品类页（二级域名）
- 关联历史文档：`产品交互说明-Heartbits ai（基于Demo）.md`、`产品交互说明-Heartbits ai-V2-新增功能.md`、`20260810-v2.1-Heartbits-ai-短剧命名统一与玩法介绍执行稿.md`

## 1. 背景

两件事促成了这次改版：

1. **品类格局变化**：平台人物从只有真人，扩展为真人 + 动漫人物的格局。产品策略上，真人再按性别拆开，形成 **女人、男人、动漫人** 三个大分类，加上三个人物混排的「全部」，共 **四种模式**。
2. **SEO 推广需要**：现有首页是唯一的人物聚合入口，所有品类挤在一个域名下，搜索引擎无法针对单一品类收录与排名，投放落地页也缺少品类聚焦的页面。需要给女人、男人、动漫三个品类各配一个独立二级域名，让每个品类都有专属的可收录、可投放的落地页。

现状（Demo 基线）：

- 首页 `/browse` 为人物混排入口，页面自上而下为：Banner 区（主标题 + 描述 + Quick Access 三张入口卡 + 右侧短剧模块）→ 人物区（Characters 标题旁有 Female / Anime / Male 筛选标签，Demo 默认选中 Female）→ FAQ → SEO 文案块 → 页脚。
- 人物数据已有品类字段（`kind`：`female` / `male` / `anime`），具备按品类拆分的数据基础。
- 筛选标签目前挂在 Characters 区标题旁，属于页内状态切换，不产生独立 URL，无法被搜索引擎当作独立页面收录。

## 2. 范围

本执行稿覆盖以下内容：

- 首页人物分类筛选标签从 Characters 区标题旁 **上移至页面顶部**，改为四个分类 Tab：All / Girls / Boys / Anime
- 新增三个品类页，使用二级域名：Girls（女人）、Boys（男人）、Anime（动漫人）
- 品类页模块裁剪：仅保留 Banner、人物列表、FAQ（按品类定制）、SEO 文案块（按品类定制）与页脚，不展示 Quick Access 与短剧模块
- 四个页面（All / Girls / Boys / Anime）通过顶部分类 Tab 跨域名互跳
- 各页面 SEO 基础口径（独立 title / description / H1 / canonical / sitemap）
- 首页 Characters 区原有 Female / Anime / Male 筛选标签的移除与新手引导指向调整

不在本执行稿范围内：

- 创建人物流程对动漫人物的支持、人物详情 / 聊天 / Discover / 短剧等其他模块的改动
- SEO 关键词策略、外链建设、投放计划（本文档只定义落地页形态与基础 SEO 口径）
- 各品类 Banner、FAQ、SEO 文案块的具体英文文案终稿（本稿仅定义定制规则与占位要求）
- 品类页的服务端渲染 / 静态化等技术实现方案（见后续技术方案文档）

## 3. 术语与定义

- `混排模式（All）`：首页默认模式，女人、男人、动漫人物混合展示
- `品类页`：只展示单一品类人物的页面，共三个：Girls（女人）、Boys（男人）、Anime（动漫人）
- `分类 Tab`：页面顶部的四个切换标签：All / Girls / Boys / Anime，作为四种模式的全局切换入口
- `Banner 区`：页面顶部主视觉区域，含主标题与品类定位文案
- `Quick Access`：首页 Banner 区内的三张快捷入口卡（Micro-Dramas / Discover / Create）
- `短剧模块`：首页的 Crowdsourced Micro-Dramas 横滑卡片区
- `品类字段`：人物实体上标识品类的字段（Demo 中为 `kind`，取值 `female` / `male` / `anime`）

## 5. F1 分类 Tab 上移至页面顶部

### 5.1 位置

- 分类 Tab 位于页面内容区最顶部、Banner 区之上（全局 TopBar 之下）。
- 原 Characters 区标题旁的 Female / Anime / Male 筛选标签移除，Characters 区只保留标题与人物列表。

### 5.2 Tab 构成与文案

| Tab | 可见文案 | 对应模式 | 目标域名 |
| --- | --- | --- | --- |
| 全部 | All | 三类人物混排 | www.heartbits.ai（主站，即现有首页） |
| 女 | Girls | 仅女人 | girls.heartbits.ai |
| 男 | Boys | 仅男人 | boys.heartbits.ai |
| 动漫 | Anime | 仅动漫人 | anime.heartbits.ai |

- Tab 顺序固定为 All → Girls → Boys → Anime。
- 当前页面对应的 Tab 呈选中高亮态，其余为默认态。
- 多语言：本期仅英文，其他语言沿用既有 fallback 机制。

### 5.3 点击行为

- 点击非当前 Tab：整页跳转至对应品类域名（跨域名跳转，非 SPA 内路由切换）。
- 点击当前 Tab：无跳转，保持当前页面。
- 与旧筛选用页内状态切换不同，新 Tab 的每次切换都产生独立 URL 的页面访问。

## 6. F2 首页保持混排（All 模式）

- 首页（主站域名）是 All 模式的唯一承载页，人物列表展示女人、男人、动漫人物的混排结果。
- Demo 中人物区默认选中 Female 的状态废弃，混排为唯一默认形态。
- 首页其余模块保持现状不变：
  - Banner 区（主标题 + 描述）
  - Quick Access 三张入口卡（Micro-Dramas / Discover / Create）
  - 短剧模块（Crowdsourced Micro-Dramas）
  - FAQ、SEO 文案块、页脚
- 人物卡点击行为不变：未登录弹登录框，登录后进入对应角色聊天页。

## 7. F3 / F4 / F5 品类页（Girls / Boys / Anime）

### 7.1 页面结构

三个品类页结构完全一致，自上而下为：

1. 全局 TopBar（与主站一致）
2. 分类 Tab（当前品类高亮）
3. Banner 区（品类定制主标题与定位文案）
4. 人物列表（仅该品类人物）
5. FAQ（品类定制）
6. SEO 文案块（品类定制）
7. 页脚

**不展示**的模块：Quick Access 三张入口卡、短剧模块（Crowdsourced Micro-Dramas）。

### 7.2 人物数据口径

| 品类页 | 域名 | 人物筛选口径 |
| --- | --- | --- |
| Girls | girls.heartbits.ai | 品类字段 = female |
| Boys | boys.heartbits.ai | 品类字段 = male |
| Anime | anime.heartbits.ai | 品类字段 = anime |

- 列表为空时展示空态提示（如 "More characters are on the way."），不出现空白页面。
- 人物卡样式与点击行为与首页一致。

### 7.3 品类定制内容

- Banner 区：主标题与描述按品类定制，围绕该品类人物的定位撰写（具体文案另出，需包含品类核心关键词）。
- FAQ：问题与答案按品类定制（如 Anime 页围绕动漫角色聊天展开），条数与首页 FAQ 相当。
- SEO 文案块：底部介绍文案按品类定制，与该品类搜索意图匹配。
- 侧边栏、TopBar、页脚等全局元素与主站保持一致，不做品类差异化。

## 8. F6 四页跨域名互跳

- 分类 Tab 在首页与三个品类页上均展示，位置、顺序、样式一致，构成四种模式的全局切换入口。
- 跳转关系：
  - All ↔ www.heartbits.ai
  - Girls ↔ girls.heartbits.ai
  - Boys ↔ boys.heartbits.ai
  - Anime ↔ anime.heartbits.ai
- 跨域名跳转为整页加载，不保留上一页面的页内状态（如列表滚动位置）。
- 用户从品类页回到混排首页的唯一产品内路径是点击 All Tab。

## 9. F7 SEO 基础口径

- 每个品类页拥有独立的 title、meta description、H1，围绕该品类核心关键词撰写（关键词清单由 SEO 策略另定）。
- 首页（All）canonical 指向主站域名；三个品类页 canonical 各自指向自身域名，不做互相 canonical。
- sitemap 新增三个品类页入口；四个页面均允许搜索引擎抓取与收录。
- 品类页保留 FAQ 与 SEO 文案块的目的即为页面提供足够的可收录文字内容，文案需按品类差异化，避免四页内容高度重复被判定为重复页面。
- 其他子页面（聊天、短剧、Discover 等）仍挂在主站域名下，本次不新增品类维度的子页面。

## 10. F8 旧筛选移除与新手引导适配

- 移除 Characters 区标题旁的 Female / Anime / Male 筛选标签及其页内筛选状态；Characters 区仅保留标题与人物网格。
- 新手引导（OnboardingTour）中指向旧筛选位置的步骤（`home-character-filter`）改为指向顶部分类 Tab，引导文案相应调整为「使用顶部分类 Tab 切换全部 / 女人 / 男人 / 动漫人物」。
- 新手引导仅在主站首页触发；品类页不触发新手引导。
- Demo 路由 `/browse` 保持不变；品类页在 Demo 中可先以 `/browse?category=girls|boys|anime` 或独立路由模拟，真实产品以二级域名为准（实现细节由技术方案确定）。

## 11. 数据与埋点口径

- 分类 Tab 点击事件：记录来源页面（all / girls / boys / anime）与目标 Tab。
- 品类页访问按域名区分统计，用于各品类 SEO 流量与投放效果评估。
- 人物卡点击、聊天发起等既有事件在品类页沿用，附加品类标识。

## 12. 兼容与迁移

- 旧筛选标签移除后，不存在依赖该页内状态的其他页面或分享链接，无需迁移。
- 已进入聊天等深层页面的用户不受本次改版影响。
- 上线前需确认三个二级域名的 DNS、证书与部署配置就绪（运维事项，不在本稿展开）。

## 13. 一句话总结

本次迭代把首页人物筛选上移到页面顶部并扩展为 All / Girls / Boys / Anime 四个分类 Tab，首页保持混排，女人、男人、动漫三个品类各自拥有独立二级域名的落地页（仅保留 Banner、人物列表与品类定制的 FAQ、SEO 文案块），四个页面通过顶部 Tab 互跳，从而支撑按单一品类做 SEO 收录与投放推广的需求。
